# Domain background knowledge

Sliding Tasks adapts a physical board-and-notes workflow. A user configures
recurring or one-time intentions, acts only on today's ordered cards, and uses
analytics rather than editable historical boards to understand the past.

## Stable product constraints

- The operational surface has one today; it is not a calendar.
- Card order is guidance, not mandatory execution order.
- Done and dismissed are conscious, distinct outcomes.
- Missed is non-action observed at day closure.
- A touch is factual interaction and carries no behavioral interpretation.
- Regular task changes affect later generations, never an existing card.
- An unresolved one-time intention is eligible again after its card is missed.
- Historical truth uses card snapshots so later task edits do not rewrite it.
- Context enrichment and inferred co-occurrence are future concerns.
